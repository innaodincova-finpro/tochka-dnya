# Безопасный выпуск «Точки дня»

Слияние изменений в `main` само по себе не развёртывает Edge Functions и не
применяет миграции production-базы. Оба действия запускаются отдельно вручную
после успешных проверок основной ветки.

## Edge Functions

Workflow `Выкладка серверных функций` запускается вручную только из `main`.
Для начала требуется точное подтверждение `DEPLOY`. Перед доступом к production
environment workflow заново выполняет полный `npm test` и локальную репетицию
восстановления. Десять функций развёртываются последовательно; автоматического
отката частичной выкладки нет.

## Миграция минимальных прав

Автоматического или ручного исполняемого workflow для production-базы сейчас
нет. Это намеренная блокировка: локальный PGlite-тест не заменяет облачную
репетицию, а прямой `psql -f` обошёл бы журнал миграций Supabase.

Файл `20260917110000_minimize_tochka_client_grants.sql` подготовлен,
идемпотентен и включён последним в recovery manifest. До production-применения
нужно в отдельном Supabase-проекте подтвердить реальную RLS-схему и работу
клиента, затем сверить migration history production. Только после этого можно
добавлять отдельный ручной workflow на основе `supabase migration list` и
`supabase db push --dry-run`, с обязательным approval владельца. Проверки должны
читать только каталог и метаданные прав, а не пользовательские строки.

## Порядок выпуска

1. Объединить только проверенный PR в `main`.
2. Дождаться успешной `Проверки приложения` для точного commit SHA.
3. Не применять миграцию, пока не пройдена отдельная Supabase-репетиция.
4. Отдельно согласовать выкладку Edge Functions и запустить её workflow.
5. Выполнить приёмку на тестовом аккаунте: вход, синхронизация, календарь,
   Telegram и push.

GitHub Pages может публиковать содержимое `main` согласно настройкам самого
репозитория. Этот механизм не управляется указанными workflow.
