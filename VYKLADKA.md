# Автоматическая выкладка

Настраивается один раз. После этого серверные функции обновляются автоматически, когда изменение основной ветки прошло обязательную проверку приложения.

Всё, что требуется, — скопировать одну строку из Supabase в GitHub.

---

## Шаг 1. Получить ключ доступа в Supabase

**Ссылка:** https://supabase.com/dashboard/account/tokens

1. Кнопка **Generate new token**.
2. Имя: `github` — любое, оно ни на что не влияет.
3. **Generate token**.
4. Появится длинная строка вида `sbp_a1b2c3...` — нажать значок копирования рядом с ней.

**Важно:** строка показывается один раз. Закроете страницу — придётся создавать заново. Ничего страшного, но лишний шаг.

---

## Шаг 2. Вставить ключ в GitHub

**Ссылка:** https://github.com/innaodincova-finpro/tochka-dnya/settings/secrets/actions

1. Кнопка **New repository secret**.
2. Поле **Name**: `SUPABASE_ACCESS_TOKEN` — ровно так, заглавными.
3. Поле **Secret**: вставить скопированную строку.
4. **Add secret**.

Готово. Ключ спрятан, в файлах его нет, посторонним он не виден.

---

## Шаг 3. Выпустить изменение

Создать отдельную ветку и pull request. Не загружать непроверенное изменение непосредственно в `main`.

Дальше произойдёт само:

1. GitHub запустит полный набор проверок.
2. После слияния сайт обновится через GitHub Pages.
3. Только после успешной повторной проверки `main` workflow «Выкладка серверных функций» отправит функции в Supabase с настройками из `supabase/config.toml`.

---

## Как узнать, что получилось

**Ссылка:** https://github.com/innaodincova-finpro/tochka-dnya/actions

Там должны успешно завершиться «Проверка приложения», публикация GitHub Pages и затем «Выкладка серверных функций».

Красный крестик — открыть строку, посмотреть, на чём остановилось, прислать снимок.

---

## Что дальше

Никаких ручных выкладок. Изменение проходит pull request и проверки; после слияния всё обновляется само. Пользователей приглашайте и проверяйте через **Ещё → Реестр пользователей** в приложении.
