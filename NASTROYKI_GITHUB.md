# Настройки GitHub: что нужно включить владельцу

Дата: 16 сентября 2026 года.

Здесь три настройки. Все делаются мышкой на сайте GitHub, ничего скачивать и устанавливать не нужно. Вместе они занимают около пятнадцати минут.

Зачем это нужно одной фразой: сейчас защита выпуска держится на правилах внутри проекта, и человек с доступом может их обойти вручную. Эти три настройки закрывают обход на стороне самого GitHub.

Слова, которые встретятся на английских страницах, ниже переведены прямо в шагах.

---

## Настройка 1. Запретить изменять рабочую версию напрямую

**Ссылка:** https://github.com/innaodincova-finpro/tochka-dnya/settings/branches

1. Откройте ссылку. Вверху страницы будет заголовок **Branches** — это список правил для основной линии приложения.
2. Нажмите кнопку **Add classic branch protection rule** (или **Add branch protection rule**, если написано так).
3. В поле **Branch name pattern** впишите одно слово: `main`. Это имя основной, рабочей версии приложения.
4. Поставьте галочку **Require a pull request before merging** — «изменение можно принять только через заявку на изменение». Появятся дополнительные строки, их менять не нужно.
5. Поставьте галочку **Require status checks to pass before merging** — «принять изменение можно только после успешных проверок».
6. Под ней поставьте галочку **Require branches to be up to date before merging** — «изменение должно быть проверено на свежей версии».
7. Там же появится поле поиска проверок. Впишите в него `safety` и выберите найденную строку. Затем так же добавьте `browser`, `proposals` и `test`. Это названия автоматических проверок приложения.
8. Пролистайте вниз и поставьте галочку **Do not allow bypassing the above settings** — «правила действуют и на владельца тоже».
9. Нажмите зелёную кнопку **Create** внизу страницы.

**Что вы увидите после:** в списке появится строка `main` с пометкой о включённых правилах.

**Что изменится в работе:** загрузить исправление сразу в рабочую версию больше не получится — ни у меня, ни у постороннего. Любое изменение сначала станет заявкой и пройдёт проверки. Ваш обычный порядок работы это не меняет: вы и сейчас принимаете изменения заявками.

## Настройка 2. Спрашивать подтверждение перед выкладкой на сервер

**Ссылка:** https://github.com/innaodincova-finpro/tochka-dnya/settings/environments

1. Откройте ссылку. Заголовок страницы — **Environments**, это список сред выкладки.
2. Если в списке уже есть строка **production** — нажмите на неё. Если её нет — нажмите **New environment**, впишите `production` и нажмите **Configure environment**.
3. Поставьте галочку **Required reviewers** — «выкладка ждёт подтверждения человека».
4. В поле рядом впишите своё имя пользователя `innaodincova-finpro` и выберите его из подсказки.
5. Нажмите **Save protection rules**.
6. Ниже найдите раздел **Deployment branches and tags**. В выпадающем списке выберите **Selected branches and tags**.
7. Нажмите **Add deployment branch or tag rule**, впишите `main`, нажмите **Add rule**.

**Что вы увидите после:** на странице среды `production` будет написано, что требуется подтверждение, и что выкладка разрешена только из `main`.

**Честно о неудобстве:** после этой настройки серверные функции перестанут выкладываться сами. Каждый раз на странице проверок появится жёлтая строка ожидания, и нужно будет нажать **Review deployments** → **Approve and deploy**. Это одно дополнительное нажатие на каждый выпуск. Взамен никакая выкладка на рабочий сервер не пройдёт без вашего ведома.

## Настройка 3. Двухшаговый вход в GitHub

**Ссылка:** https://github.com/settings/security

1. Откройте ссылку. Раздел называется **Two-factor authentication** — «вход в два шага».
2. Если написано **Two-factor authentication is enabled** — уже всё сделано, переходите к следующему разделу этой инструкции.
3. Если нет — нажмите **Enable two-factor authentication**.
4. Выберите **Set up using an app** и наведите камеру телефона на квадратный код. Подойдёт любое приложение-подтверждение на телефоне.
5. Введите шесть цифр, которые покажет приложение.
6. GitHub покажет список запасных кодов. **Сохраните их**: распечатайте или запишите в место, где храните пароли. Они нужны, если телефон потеряется.

**Что вы увидите после:** зелёная надпись **Two-factor authentication is enabled**.

## Как сообщить, что сделано

Пришлите три снимка экрана: список правил основной линии, страницу среды `production` и строку о двухшаговом входе. После этого я проверю на сервере два случая: что изменение не из рабочей версии не получает выкладку и что проверенное изменение выкладывается. Результат запишу в отчёт.

## Если что-то не совпало

Названия кнопок на GitHub иногда меняются. Если нужной кнопки нет — пришлите снимок страницы целиком, я подскажу по нему. Ничего наугад нажимать не нужно.

## Что делать вам

Выполнить три настройки выше по порядку и прислать три снимка экрана.
