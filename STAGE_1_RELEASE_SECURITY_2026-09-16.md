# Этап 1. Защита выпуска — промежуточный отчёт

Дата: 16 сентября 2026 года.

## Итог текущей правки

Опасный сценарий замечания №1 воспроизведён постоянной проверкой и исправлен в рабочей копии. Исправление ещё не опубликовано и поэтому замечание №1 пока не закрыто.

## Сделано

- Удалён ручной запуск рабочей выкладки, который позволял обойти обязательную проверку.
- Выкладка разрешена только после успешной проверки изменения, отправленного в основную линию проекта `main` из этого же репозитория.
- Для выкладки используется точный идентификатор проверенного исходного кода без запасного перехода на другую версию.
- Получение исходников при выкладке не сохраняет учётные данные GitHub.
- Для рабочей выкладки указана защищаемая среда `production`.
- Одновременные рабочие выкладки запрещены.
- Все сторонние действия GitHub закреплены полными неизменяемыми идентификаторами.
- Supabase CLI закреплён на версии `2.117.0` вместо автоматически меняющейся версии `latest`.
- Создана постоянная проверка `deployment-security-regression.cjs`; она автоматически запускается перед каждым `npm test`.
- Выкладка ограничена точным списком всех 10 Edge Functions «Точки дня». Для `tochka-assistant-calendar` и `tochka-assistant-sandbox` добавлены безопасные `OPTIONS` smoke-проверки: они не читают данные и не выполняют запись.

## Проверено

- До исправления новая проверка остановилась на изменяемом подключении `actions/checkout@v4`; дефект воспроизведён.
- После исправления отдельная проверка защиты выкладки прошла.
- Проверка сборки и версии Telegram-функции прошла.
- Полный обязательный набор `npm test` прошёл с кодом завершения 0.
- Проверка оформления изменений `git diff --check` прошла.
- История проекта проверена по признакам рабочих ключей GitHub, Supabase, Telegram и AWS. Обнаружена только заведомо искусственная строка Telegram в автоматической проверке; рабочего секрета по проверенным признакам не найдено.

## Не сделано

- Изменения не отправлены в GitHub и не опубликованы.
- Защита основной линии проекта и правила среды `production` в настройках GitHub ещё не подтверждены.
- Минимальные права рабочего ключа Supabase ещё не подтверждены в аккаунте владельца.
- Многофакторная защита GitHub и Supabase ещё не подтверждена.
- Ограничение попыток входа Supabase, список разрешённых источников страницы и проверка OWASP ASVS уровня 1 ещё не завершены.
- Нормальная рабочая выкладка и отклонение недоверенной правки ещё не проверены на сервере GitHub.
- Supabase CLI выкладывает Edge Functions последовательно; доказанной атомарной групповой выкладки и безопасного автоматического отката в этом процессе нет. Вся сборка и список функций проверяются до первой выкладки, а при сбое workflow явно перечисляет уже обновлённые функции без имитации отката.

## Следующий шаг

Проверить и настроить защиту основной линии и среды `production` в GitHub, после чего отправить изменения отдельным запросом на включение, дождаться всех проверок и только с отдельного разрешения опубликовать. Затем подтвердить сервером два сценария: недоверенная правка не получает рабочую выкладку, а точный проверенный код основной линии выкладывается успешно.

## Что делать вам

Пока ничего менять не нужно. Перед действиями владельца будет подготовлена отдельная короткая инструкция со ссылками и пронумерованными шагами.
