# Этап 1. Защита выпуска

Дата отчёта: 16 сентября 2026 года.
Проверенная версия приложения: 5.9.9.
Изменение в основной линии: `56ea7d6bfc5123f6e374cbb82f011f9771f06760` — «Защитить рабочую выкладку проверенной версией» (запрос на изменение [№83](https://github.com/innaodincova-finpro/tochka-dnya/pull/83)).

## Итог

Изменение принято в основную линию, проверено и выложено на сервер 16 сентября в 16:18–16:19 по московскому времени. Замечание №1 исходного аудита закрыто по части, которая зависит от кода. Осталась часть, которая зависит от настроек в личных кабинетах GitHub и Supabase: её может выполнить только владелец.

Прежняя редакция этого отчёта говорила, что изменения «не отправлены и не опубликованы». На 16 сентября это неверно: они отправлены, приняты и выложены. Отчёт исправлен именно поэтому.

## Сделано в коде

- Удалён ручной запуск рабочей выкладки, который позволял обойти обязательную проверку.
- Выкладка разрешена только после успешной проверки изменения, принятого в основную линию `main` из этого же проекта, а не из чужой копии.
- Для выкладки берётся точный проверенный исходный код по его номеру, без запасного перехода на другую версию.
- Получение исходников при выкладке не сохраняет учётные данные GitHub.
- Для рабочей выкладки указана защищаемая среда `production`.
- Одновременные рабочие выкладки запрещены.
- Все сторонние действия GitHub закреплены полными неизменяемыми номерами.
- Supabase CLI закреплён на версии `2.117.0` вместо автоматически меняющейся `latest`.
- Создана постоянная проверка `deployment-security-regression.cjs`; она запускается перед каждым `npm test`.

## Два сценария защиты выкладки

1. **Проверенный код основной линии выкладывается.** Подтверждено: запуск 80 отработал сразу после успешной проверки изменения №83 и дошёл до ответа сервера.
2. **Изменение не из основной линии рабочую выкладку не получает.** Подтверждено частично: 16 сентября в 16:14 по изменению из отдельной линии `fix/release-security` прошли все проверки, но выкладка не запускалась — за этот день есть единственный запуск выкладки, и он относится к основной линии. Живой опыт с чужой копией проекта не проводился: для него нужна вторая учётная запись и разрешение владельца. Запрет на чужую копию закреплён в правиле выкладки и в постоянной проверке.

## Что зависит от владельца и пока не подтверждено

- Защита основной линии в настройках GitHub: запрет прямой загрузки и обязательные проверки перед приёмом изменения.
- Правила среды `production`: обязательное подтверждение перед выкладкой.
- Двухшаговый вход в GitHub и в Supabase.
- Минимальные права рабочего ключа Supabase, ограничение попыток входа, список разрешённых адресов страницы.

Для этих действий подготовлены отдельные инструкции: [настройки GitHub](NASTROYKI_GITHUB.md) и [настройки Supabase](NASTROYKI_SUPABASE.md).

## Что делать вам

Ничего менять прямо сейчас не нужно. Если хотите убедиться своими глазами, что на телефоне открывается свежая версия: откройте приложение, зайдите в «Ещё» и посмотрите строку версии внизу — там должно стоять 5.9.9. Если стоит более старый номер, закройте приложение полностью и откройте снова.
