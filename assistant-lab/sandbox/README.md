# Подтверждённое сохранение в изолированный тестовый список

Страница web/sandbox.html, функция tochka-assistant-sandbox (JWT включён).
Сохранение только после нажатия владельцем, проверенным через Supabase Auth.
Сервер не принимает user_id от браузера. Сессия браузера только в памяти.
Таблица tochka_assistant_sandbox закрыта для anon/authenticated.

RPC блокирует строку pilot и сравнивает точную версию и содержимое показанного
черновика. Повтор подтверждения той же версии идемпотентен; изменившийся
черновик, выключенный помощник, неполные и просроченные предложения отклоняются.
30 минут для нового сохранения. Уже сохранённая версия повторно не вставляется.
Каждое новое сообщение боту создаёт новую версию; семантическое объединение
разных версий не реализовано. Список отображает последние 100 записей.

Нет доступа к user_app_data, рабочему плану, расходам, заметкам, push или ИИ.
Это тестовый серверный список, не интеграция с синхронизацией рабочего приложения.
Удаление учётной записи pilot каскадно удаляет тестовый список.

Проверки из корня репозитория (npm install):
node --test assistant-lab/sandbox/test.mjs
node assistant-lab/sandbox/sql-test.mjs
node assistant-lab/sandbox/web-test.cjs
SQL выполняется в локальном PGlite с минимальной схемой pilot.
Две вкладки проверяются в jsdom с имитацией API. Реальная приёмка под входом
владельца остаётся отдельным шагом; тесты не используют личные данные.

Развёртывание: schema.sql через миграции Supabase; index.ts, handler.mjs,
common.mjs и proposal.mjs в отдельной Edge Function с verify_jwt=true.
web/ публикуется в /tochka-assistant/ на GitHub Pages владельца.
Откат: убрать ссылку/страницу и функцию; таблицу можно оставить для сохранности
тестовых записей. Рабочая версия и существующий receiver не меняются.
