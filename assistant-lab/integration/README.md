# Помощник внутри «Точки дня» — подготовка в тестовой ветке

Статус: исходники интеграции, не опубликованы в рабочий main.
Базовый main: ca04694eae174596e6f613f1fd0464f77d6a6dd1.
Подтверждения пользователя в тестовом календаре: импорт встречи и изменение16→17.
Они не являются приёмкой рабочего облака с новой интеграцией.

Что меняется:
- «Ещё» → «Встречи помощника»: список импортированных встреч тестового календаря.
- Выбор показывает точную дату, время, название, адрес; запись только по
  «Добавить в мой план». Только event в этом этапе.
- Перед подтверждением перечитывается серверная версия; изменившаяся
  встреча требует нового просмотра.
- Чтение помощника: JWT текущей сессии, только owner через существующий
  tochka-assistant-calendar/list. Сам endpoint рабочие данные не читает.
- Запись в S.ev через обычный save/pushCloud, включая mergeThree и optimistic
  updated_at compare-and-swap. Пишет клиент под своей сессией/RLS.
- Идентификатор SHA256(user+canonical source_version); неизменяемый ledger
  assistantImports предотвращает повтор и восстановление удалённой записи.
  ledger валидируется, сохраняется в копиях и объединяется в mergeStates.
- Повтор не перезаписывает последующие ручные правки. Отдельная версия
  исходного черновика — отдельная запись, семантического dedup нет.
- Одна локальная резервная копия состояния до добавления, ключ
  tochka-dnya-v3:assistant-before:<user>. Ошибка локальной записи останавливает
  добавление до изменения S.
- Потеря связи после добавления показывается как неподтверждённое облачное
  сохранение; повторное нажатие не создаёт вторую запись.
- Смена аккаунта/эпохи прекращает действие; доступ закрыт при cloudConflict
  и повреждённых данных. Предпросмотр очищается при смене аккаунта.
- Два новых скрипта включены в shell service worker с отдельным cache version.

Проверка: node assistant-import-regression.cjs; npm test.
Новый тест загружает реальный index.html в jsdom и вызывает реальный
save/pushCloud с fake Supabase query API (без личных записей/сетевых запросов).
Проверяет UI до/после подтверждения, вторую вкладку, изменение и удаление,
ledger после слияния/истечения tombstone, смену аккаунта, изменившийся
предпросмотр и сетевой сбой с повторной синхронизацией.
Дополнительно11существующих core-data-regression сценариев пройдены.

Осталось перед выпуском:
- Полная браузерная приёмка сборки и облака на изолированной копии данных.
- Реальная синхронизация между устройствами под входом владельца.
- Проверка действующих push после добавления (они зависят от рабочего payload).
- Перед main свежая резервная копия данных и ограниченный запуск только владельцу.
- Расходы/заметки пока не интегрированы.
Не включать кнопку в общедоступный релиз без завершения этих проверок.
Откат: предыдущий index/sw и удаление новых script references; ledger оставить
в данных, чтобы последующее включение не импортировало встречи повторно.
