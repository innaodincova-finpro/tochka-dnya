# Напоминания «Точки дня» в Telegram

## Поведение

Отдельный серверный обработчик `tochka-telegram-reminders` раз в минуту читает текущие встречи владельца из `user_app_data`. Отправляет в привязанный частный чат @Inna_Assis_bot за час, по Москве. Заголовок, дата, время и адрес берутся из записи. Если запуск задержался, текст указывает оставшееся количество минут. Приложение может быть закрыто. ИИ, распознавание голоса и квота 20 обращений не используются.

Повторы поддерживают существующие значения `week`, `month`, `year`. Удалённые встречи, отметки удаления и выполненные на соответствующую дату пропускаются. Перед резервированием и непосредственно перед отправкой перечитываются настройки, привязка, доступ и данные; SQL также сравнивает текущее событие с кандидатом. Перенос меняет ключ напоминания. Уже доставленное сообщение отозвать переносом нельзя.

Текст в боте: «Напоминания», «Включи напоминания», «Отключи напоминания». Есть эквиваленты `/reminders`, `/reminders_on`, `/reminders_off`. Команды работают до дневной квоты. `/stop` останавливает и обработку записей, и напоминания. Push и Apple Calendar независимы: выключение Telegram их не выключает.

## Границы надёжности

- Окно отправки — первые 5 минут после расчётного времени. После более длительного сбоя поздние сообщения не рассылаются.
- Уникальный ключ по владельцу/событию/дате/времени предотвращает повтор при параллельных или повторных запусках. Получатель перепроверяется по связке аккаунта, членства и Telegram-привязки; токен бота проверяется через getMe.
- Подтверждённое ограничение Telegram 429 допускает до 3 попыток с retry_after и интервалом не меньше минуты. При таймауте, непонятном ответе или незавершённой попытке автоматического повтора нет: Telegram не предоставляет ключ идемпотентности, поэтому гарантировать одновременно доставку и отсутствие дублей невозможно.
- Изменение после последней проверки может совпасть с отправкой. Уже принятый Telegram запрос не отменяется.
- Одна итерация ограничена десятью новыми попытками и 40 секундами начала работы цикла. Крупные группы встреч обрабатываются следующими запусками в пределах окна.
- `sent` означает принятие сообщения API Telegram, а не просмотр или звук на телефоне.

## Доступ и развёртывание

`schema.sql` добавляет только две служебные таблицы и SECURITY INVOKER RPC. RLS включён, PUBLIC/anon/authenticated не имеют доступа; service_role имеет необходимые права. Отсутствие пользовательских RLS-политик здесь намеренно: прямой клиентский доступ запрещён. Секрет расписания генерируется базой, не публикуется в исходниках, передаётся через x-job-key; verify_jwt отключён только у обработчика с собственной проверкой секрета.

Конфигурация создаётся выключенной. После развёртывания обработчика применяется `cron.sql`; активация выполняется для одного ранее проверенного владельца. Ключи, существующие пользовательские записи, схемы других каналов и их cron не изменяются.

Развёртывание 12.09.2026: новая функция v1; получатель сообщений v12; все 14 файлов повторно получены и побайтово сверены. Миграции: `tochka_telegram_reminder_storage`, `tochka_telegram_reminder_schedule`. Напоминания включены только для уже привязанного владельца. Подтверждение фактического уведомления на телефоне остаётся открытым.

## Проверки и сопровождение

`node --test assistant-lab/reminders/*.test.mjs assistant-lab/direct-telegram/*test.mjs` — восемь тестовых файлов. Интеграционный тест выполняет реальную функцию резервирования в PGlite с искусственными аккаунтами и подменённым Telegram: дубли, отмена после резервирования, таймаут, 429, запрет доступа, выключение, выполненные встречи, группа из 12 событий, команды и сохранность записей. Тест расписания проверяет переносы, повторения, полночь и адрес.

Статус: `tochka_telegram_reminder_config.last_run_at/last_result`. Журнал доставки хранится 30 дней; секреты, тексты и адреса в него не записываются. Для отката отключить enabled у конфигурации или cron `tochka-telegram-every-minute`; записи пользователя восстанавливать не требуется. Не удалять журнал и не переводить unknown/claimed в retry автоматически.
