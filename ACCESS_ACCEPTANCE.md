# Учёт доступа к «Точке дня», 5.8.11

Реестр использовал общий список Auth и глобальное время входа, поэтому показывал пользователей «Кабинета студента». Теперь источник списка — tochka_members. Начальный перенос включает только аккаунты с сохранением user_app_data и владельца; app_data не служит основанием доступа. Историческое время активности берётся из сохранения «Точки дня», будущие открытия регистрирует tochka_visit. Глобальное last_sign_in_at не используется для статистики Реестра.

Владелец может удалить любого участника, кроме себя, с подтверждением адреса и последствий. Удаляются только user_app_data, подписки и доставки уведомлений «Точки дня». Отметка отзыва остаётся, RLS и блокировка строки запрещают восстановить облачные данные старым клиентом. Общий аккаунт Auth, сессии и app_data сохраняются. Локальные копии на устройствах не удаляются; приложение может работать локально.

Повторное приглашение восстанавливает доступ. Для существующего подтверждённого аккаунта выдаётся обычная ссылка и инструкция входа с существующим паролем, без сброса пароля другого приложения. Для нового аккаунта выдаётся персональная ссылка активации, после регистрации доступа. Старая функция полного удаления приглашения заменена отказом с просьбой обновить Реестр.

Проверки:
- access-test.cjs: SQL, права владельца, защита владельца, отсутствие самовыдачи доступа, отзыв, запрет повторной записи, сохранность другого приложения, повторная выдача.
- access-test.sql: те же сценарии на живой схеме с временными аккаунтами внутри BEGIN/ROLLBACK; успешно выполнено, рабочие аккаунты не удалялись.
- access-api-test.cjs: раздельный список, активность только приложения, удаление активированного, проверка адреса/id, два вида приглашений.
- access-ui-test.cjs: кнопка удаления активированного пользователя, отмена, подтверждение, обновление списка, инструкции существующего аккаунта.
