# 5.8.13 — защита синхронизации

Отметки удаления объединяются по id с выбором наиболее свежей даты независимо от порядка устройств, включая быстрые ветви mergeThree. Старые отметки без даты остаются действующими. Убран лимит 4000: действующие отметки не отбрасываются по количеству; срок хранения 180 дней сохранён.

Повреждённые del, даты удаления и суммы логического/объектного типа отвергаются. Числа, числовые строки и старые записи без del остаются совместимыми. Исходная повреждённая локальная база сохраняется, автозапись блокируется существующим механизмом. mergeThree не меняет аргументы.

11 новых сценариев core-data-regression.cjs: порядок слияния, быстрые ветви, 4100 удалений, дубли, старый формат, повреждения, суммы, удаление/правка с явным выбором, неизменность входов, 1500 заметок, сохранность повреждённой базы. Существующие тесты голосового ввода и синхронизации также выполняются. Это тесты в jsdom, не нагрузочный тест нескольких реальных пользователей.
