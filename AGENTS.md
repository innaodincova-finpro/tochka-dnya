# Правила работы с проектом «Точка дня»

Эти правила действуют для всего репозитория.

1. Перед изменениями восстановления прочитать
   `RECOVERY_CHANGE_CONTROL_2026-09-17.md`.
2. Не менять production Supabase, пользовательские данные, секреты,
   опубликованный сайт и расписания без отдельного явного согласия владельца.
3. Не смешивать объекты Studkab и `public.app_data` с Tochka-only rebuild.
   Общую миграцию разрешено включать только через документированный безопасный
   extract или guards, проверенные на пустом Tochka-only проекте.
4. Исторические миграции не переписывать задним числом. Recovery extracts должны
   содержать provenance: исходный путь, commit и SHA-256.
5. Синтетический PGlite-тест, статическая SQL-проверка и настоящая облачная
   репетиция — разные уровни доказательств. Не называть первые два production
   restore test.
6. Каждый дефект сначала фиксировать проверкой. После исправления эта проверка
   остаётся в обязательном наборе.
7. Изменения приложения выполнять последовательно. После каждого этапа
   запускать относящиеся к нему тесты и полный `npm test`.
8. Не помещать в Git пользовательские строки, Auth-экспорты, Storage-файлы,
   токены, ключи и значения секретов.
9. Не считать recovery завершённым без восстановления в отдельном Supabase,
   проверки Auth UUID, данных, Storage, RLS, Edge Functions и измерения RPO/RTO.
10. Отчёт обязан перечислять: сделано, проверено, не сделано, следующий шаг и
    требуемое действие владельца либо прямо указывать, что оно не требуется.
