# Восстановление базы «Точки дня»

Этот порядок предназначен только для нового пустого проекта Supabase. Он создаёт структуру базы, правила доступа, хранилище документов, push и Telegram-часть. Пользовательские записи и секреты в репозитории не хранятся: их восстанавливают отдельно из резервной копии проекта.

## Порядок

1. Создать новый проект Supabase и получить прямую строку подключения к Postgres.
2. Из корня репозитория выполнить:

   ```sh
   psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/rebuild.sql
   ```

3. Задать секреты функций в настройках нового проекта. Не помещать их в GitHub или SQL-файлы.
4. Запустить workflow «Выкладка серверных функций» вручную с новым идентификатором проекта только после отдельной проверки конфигурации.
5. Выполнить `npm test`, затем проверить вход, сохранение одной тестовой записи, документ, привязку Telegram и напоминание.

Если любая SQL-команда завершается ошибкой, выполнение останавливается. Продолжать с середины нельзя: нужно удалить тестовый проект, исправить причину и повторить на новом пустом проекте.

## Что не восстанавливает этот сценарий

- учётные записи и действующие сессии Auth;
- пользовательские записи и загруженные файлы;
- секреты Telegram, DeepSeek, VAPID и служебные ключи;
- настройки расписания, зависящие от адреса нового проекта.

Это данные резервной копии и конфигурация окружения, а не схема базы.
