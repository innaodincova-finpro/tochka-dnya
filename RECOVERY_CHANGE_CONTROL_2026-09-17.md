# Контроль изменений восстановления «Точки дня»

Дата: 17 сентября 2026 года.

Этот документ — самостоятельный действующий протокол для recovery-работ. Он не
переносит незавершённый протокол из другой ветки.

## Граница

Репозиторный rebuild предназначен для нового пустого Tochka-only проекта.
Production-проект общий со Studkab, поэтому общий production dump является
отдельным аварийным артефактом и не заменяет Tochka-only rebuild.

## Уровни доказательств

1. **Статическая dependency validation** — проверяет файлы, порядок,
   зависимости, provenance, конфигурацию и отсутствие известных опасных ссылок.
2. **Синтетическая локальная репетиция** — `npm run test:recovery` проверяет
   упрощённую PGlite-базу.
3. **Чистый PostgreSQL execution** — полный `rebuild.sql` исполняется без
   ошибок в совместимом пустом PostgreSQL с требуемыми Supabase-схемами.
4. **Изолированная Supabase-репетиция** — восстанавливаются Auth-связи, строки,
   Storage, функции, секреты тестовой среды и Cron.
5. **Production readiness** — подтверждены внешние копии, расписание, retention,
   RPO/RTO и квартальная репетиция.

Уровень нельзя подменять более слабым уровнем.

## Репозиторный gate

Перед передачей на review обязательны:

- ровно 22 ordered SQL source;
- отсутствие прямого включения mixed migrations `20260915133000` и
  `20260915140000`;
- provenance и исходный SHA-256 у Tochka-only recovery extracts;
- все ссылки extracts разрешаются на объекты, созданные раньше в rebuild;
- исходники и явный `verify_jwt` всех 10 Edge Functions;
- отсутствие production URL в переносимых Cron-шаблонах;
- актуальные tree SHA-256 в recovery manifest;
- migration `20260917110000_minimize_tochka_client_grants.sql` стоит последней,
  а её SHA-256 совпадает с recovery manifest;
- `npm run test:recovery`, `npm test` и `git diff --check` проходят.

## Gate полного восстановления

Статус «восстановление проверено» разрешён только после отдельного Supabase:

- сохранены Auth UUID/identities либо доказан согласованный способ повторной
  регистрации без нарушения связей;
- восстановлены production-строки и проверены количества/контрольные суммы;
- восстановлены Storage paths и бинарные SHA-256;
- заданы новые тестовые секреты, webhook и адрес тестового проекта;
- развёрнуты и проверены все функции;
- RLS запрещает чтение чужих данных;
- Cron не отправляет сообщения реальным пользователям;
- повторный запуск имеет документированный результат;
- измерены RPO и RTO.

## Текущее ограничение среды

На этапе подготовки 17 сентября 2026 года в рабочей среде не обнаружены
`psql`, `postgres`, `initdb` и Docker. Поэтому выполнена статическая
dependency validation, но не clean PostgreSQL execution и не облачная
репетиция.
